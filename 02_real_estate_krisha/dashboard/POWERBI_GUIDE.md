# Дашборд в Power BI: пошаговая сборка

**Для кого:** директор агентства и брокеры. **Вопрос дашборда:** *какую квартиру в Астане посоветовать
инвестору и что честно сказать ему про доходность?*

Дашборд из 3 страниц — каждая отвечает на один вопрос директора агентства:

| № | Страница | Вопрос |
|---|---|---|
| 1 | Обзор рынка | Сколько стоит купить и снять квартиру в каждом районе? |
| 2 | Доходность | Что покупать и выгоднее ли это депозита? |
| 3 | Шорт-лист | Какие конкретные квартиры смотреть брокеру? |

Таблицы `history` и `hypotheses` в дашборде не используются — история цен и проверка гипотез
описаны в README и ноутбуках.

---|---|---|
| 1 | Обзор рынка | Сколько стоит купить и снять квартиру в каждом районе |
| 2 | Доходность | Какие сегменты (район × комнаты) окупаются быстрее |
| 3 | Инфляция и депозит | Выгоднее ли квартира, чем депозит, при разных сценариях |
| 4 | Шорт-лист | Конкретные объявления для брокера со ссылками на krisha.kz |
| 5 | Гипотезы | Что подтвердилось статистически |

---

## Шаг 0. Подготовка

1. Установи **Power BI Desktop** (бесплатно, Microsoft Store или сайт Microsoft; работает только на Windows).
2. Запусти ноутбук `07_powerbi_export.ipynb` — он создаст папку `dashboard/data/` с 6 CSV-файлами.

## Шаг 1. Загрузка данных

1. Главная → **Получить данные → Текст/CSV**.
2. По очереди загрузи все файлы из `dashboard/data/`. В окне предпросмотра проверь, что
   **Источник файла = 65001: Юникод (UTF-8)** и разделитель — запятая. Нажми **Загрузить**.
3. Проверь типы колонок (вкладка **Данные**, слева). Если Power BI ошибся, исправь через **Преобразовать данные**:
   - `price_kzt`, `price_per_m2`, `est_rent_month`, `fair_price` — **Целое число**;
   - `gross_yield`, `net_yield`, `real_net_yield`, `discount_to_fair`, `roi_*`, `deposit_*`, `median_*`, `effect`, `ci_*` — **Десятичное число**;
   - `in_client_budget`, `is_undervalued` — **True/False**;
   - `listing_id` — **Целое число**.

   ⚠️ Если в десятичных числах точка не распознаётся (региональные настройки Windows с запятой):
   Файл → Параметры → Текущий файл → Региональные параметры → **Английский (США)**, затем обнови данные.

## Шаг 2. Модель данных (связи)

Вкладка **Модель** (слева, третья иконка). Перетащи поля, чтобы создать связи:

| Из | В | Тип |
|---|---|---|
| `districts[district]` | `flats[district]` | Один ко многим (1:*) |
| `districts[district]` | `sale_investment[district]` | Один ко многим (1:*) |

Таблицы `history`, `roi_scenarios`, `hypotheses` ни с чем не связываем — они самостоятельные.

**Сортировка районов:** в таблице `districts` выдели колонку `district` → Инструменты для столбцов →
**Сортировать по столбцу → district_order**. Так районы везде пойдут с левого берега на правый.

**Формат колонок-ссылок:** выдели `sale_investment[url]` → Инструменты для столбцов → Категория данных →
**URL-адрес веб-страницы**. То же для `flats[url]`.

## Шаг 3. Меры

Создай пустую таблицу для мер: Главная → **Ввести данные** → назови `_Меры` → Загрузить.
Затем для каждой меры из файла `measures.dax`: выдели таблицу `_Меры` → Моделирование → **Новая мера** →
вставь текст меры целиком → Enter.

Формат мер (вкладка «Инструменты мер»):
- доходности, доли и ROI — **Процент**, 1 знак после запятой;
- цены и аренда — **Целое число** с разделителем разрядов;
- `Окупаемость, лет` — десятичное, 1 знак.

## Шаг 4. Тема оформления

Вид → Темы → выбери спокойную тему (например, «Executive»). Цвета берегов, как в ноутбуках:
**левый берег — синий `#4C72B0`, правый — оранжевый `#DD8452`**. Задаются в «Цвета данных» у каждого графика.

## Страница 1. Обзор рынка

```
┌─────────────────────────────────────────────────────────────────────┐
│  Рынок квартир Астаны: продажа и аренда          [срез: Берег] [Комнаты]│
├───────────┬───────────┬───────────┬───────────┬─────────────────────┤
│ Объявлений│ Медиана   │ Медиана   │ Медиана   │ Медиана аренды      │
│ продажи   │ цены, млн │ аренды/мес│ цены за м²│ за м²               │
├───────────┴───────────┴───────────┴───────────┴─────────────────────┤
│ Цена за м² по районам (продажа)   │ Аренда за м² по районам          │
│ ▇▇▇▇▇▇▇▇ Есильский                │ ▇▇▇▇▇▇ Есильский                 │
│ ▇▇▇▇▇▇▇ Нура  ...                 │ ...                              │
├───────────────────────────────────┼──────────────────────────────────┤
│ Структура предложения по комнатам │ Аренда на 1 продажу по районам   │
│ (продажа vs аренда)               │                                  │
└───────────────────────────────────┴──────────────────────────────────┘
```

| Визуал | Настройки |
|---|---|
| **Срезы** (×2) | `districts[bank]`; `flats[rooms]`. Стиль — «Плитка» |
| **Карточки** (×5) | `Объявлений продажи`, `Медиана цены продажи, млн`, `Медиана аренды в месяц`, `Медиана цены за м2 (продажа)`, `Медиана аренды за м2` |
| **Линейчатая диаграмма** | Ось Y: `districts[district]`; значение: `Медиана цены за м2 (продажа)`; цвет столбцов — условное форматирование по мере `Цвет берега` |
| **Линейчатая диаграмма** | то же, значение `Медиана аренды за м2` |
| **Гистограмма с группировкой** | Ось X: `flats[rooms]`; значение: мера `Доля объявлений` (формат — процент); условные обозначения: `flats[deal]` |
| **Гистограмма** | Ось X: `districts[district]`; значение: `Аренда на 1 продажу`; добавь линию константы = 1 (вкладка «Аналитика») |

**Текстовое поле с выводом** (внизу страницы): «Левый берег дороже за м² на 30–50%, а аренда там выше лишь на ≈12% —
поэтому правый берег доходнее. В Есильском районе на одну продажу приходится 1,2 объявления аренды — высокая конкуренция за арендатора».

## Страница 2. Доходность

| Визуал | Настройки |
|---|---|
| **Фильтр страницы** | `districts[bank]` — только «Левый берег» и «Правый берег» |
| **Срезы** | `districts[bank]` (синхронизирован со страницей 1), `sale_investment[rooms]` |
| **Карточки** (×3) | `Чистая доходность` (≈8,5%), `Реальная доходность` (≈−2,3%), `Окупаемость, лет` (≈11,7) |
| **Матрица** (главный визуал) | Строки: `districts[district]`; столбцы: `sale_investment[rooms]`; значения: `Чистая доходность`. Условное форматирование → Цвет фона → Градиент: мин `#C44E52`, середина `#F3E79B`, макс `#55A868` |
| **Гистограмма с группировкой** «ROI за 5 лет против депозита» | Ось X: `roi_scenarios[scenario]` (сортировка по `scenario_order`); значение: `ROI за 5 лет`; условные обозначения: `roi_scenarios[bank]`. Аналитика → линия константы **0,985** «Депозит 14,7% за 5 лет» |

**Вывод на странице:** «Лучшие сегменты — однушки на правом берегу (≈9,8–10,6% чистыми). Одна аренда (≈8,5%)
проигрывает депозиту (14,7%) и инфляции (≈11%). Квартира выгоднее депозита только если цены растут
не медленнее инфляции; если рынок повторит 2016–2025, результат ≈ депозиту».

## Страница 3. Шорт-лист для брокера

| Визуал | Настройки |
|---|---|
| **Срезы** | `districts[district]`, `sale_investment[rooms]`, **срез-диапазон** `sale_investment[price_mln]` (выставить 20–50) |
| **Карточки** (×2) | `Квартир на продажу`, `Недооценённых квартир` |
| **Таблица** (главный визуал) | `district`, `rooms`, `area_m2`, `floor_type`, `price_mln`, `est_rent_month`, `net_yield`, `payback_years`, `discount_to_fair`, `url`. Сортировка по `net_yield` по убыванию. Условное форматирование `net_yield` — гистограммы данных |

**Подпись под таблицей:** «Высокая доходность и большой дисконт часто означают проблему с квартирой
(состояние, дом, документы). Список — повод посмотреть объект первым, а не готовая рекомендация».

## Шаг 5. Финальные штрихи

1. На каждой странице — заголовок-вопрос (например, «Где квартира окупается быстрее?») и 1–2 строки вывода.
2. Вид → **Синхронизация срезов**: срез «Берег» синхронизировать на страницах 1 и 2.
3. Кнопки навигации между страницами: Вставка → Кнопки → Навигатор → **Навигатор страниц**.
4. Сохрани файл как `dashboard/krisha_astana.pbix`.

## Шаг 6. Публикация (для ссылки в README)

**Вариант А — Power BI Service (нужен рабочий/учебный аккаунт Microsoft):** Главная → **Опубликовать** →
в Power BI Service: Файл → Внедрить отчёт → **Опубликовать в Интернете** → получишь публичную ссылку.

**Вариант Б — без аккаунта:** сделай скриншоты каждой страницы и экспортируй отчёт в PDF
(Файл → Экспорт → **Экспорт в PDF**). Скриншот главной страницы вставь в README, PDF положи в `dashboard/`.
Файл `.pbix` тоже положи в репозиторий — его можно открыть в бесплатном Power BI Desktop.
